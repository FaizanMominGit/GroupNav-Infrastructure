### 1.2 Multi-Stack Architecture Setup
Instead of accepting the single monolithic stack generated by CDK (`_init-stack.ts`), we decoupled the application into dedicated stack definitions from day one:

- **CDK Entrypoint ([bin/groupnav.ts](file:///c:/Users/faizan/Downloads/AWS/bin/groupnav.ts))**:
  - Initializes the CDK App and configures region defaults (`ap-south-1` for low latency in Mumbai with identical Free Tier cost).
  - Instantiates `NetworkStack` and `AuthStack` as isolated top-level constructs rather than a monolith.
  - Passes explicit environment metadata (`account`, `region`, and stack descriptions) to guarantee deterministic deployments across team members and CI/CD pipelines.

- **Stack Definitions**:
  - **[lib/network-stack.ts](file:///c:/Users/faizan/Downloads/AWS/lib/network-stack.ts)**: Encapsulates all network foundation resources (VPC, subnets, gateway endpoints, and security groups).
  - **[lib/auth-stack.ts](file:///c:/Users/faizan/Downloads/AWS/lib/auth-stack.ts)**: Encapsulates identity and location services (Cognito User Pool, Identity Pool, and Amazon Location Service).

- **CDK App Target ([cdk.json](file:///c:/Users/faizan/Downloads/AWS/cdk.json))**:
  - Re-pointed the app execution target to `bin/groupnav.ts` using `tsx` for high-speed TypeScript execution.
  - Removed temporary initialization artifacts (`bin/_init.ts`, `lib/_init-stack.ts`, `test/_init.test.ts`).

## 2. Why It Was Done This Way

### 2.1 Enforcing Blast Radius Isolation From Day One
- In standard tutorials, CDK projects start with one large stack (`GroupnavStack`). As resources grow (VPC, Database, Cognito, Lambda, CI/CD), any minor change triggers a full template diff across all resources.
- If a stateful database or network interface is mixed into the same stack as Lambda functions or Cognito clients, CloudFormation stack updates can lock or fail catastrophically.
- By separating into `NetworkStack` and `AuthStack` immediately:
  - Changes to Cognito or Location Service policies cannot disrupt the VPC or subnet route tables.
  - `cdk diff NetworkStack` and `cdk diff AuthStack` remain pinpointed, legible, and safe for team PRs.

### 2.2 Independent Deployability for Flutter Mobile Team
- Section 1 of [GroupNav-Infrastructure-Plan.md](file:///c:/Users/faizan/Downloads/AWS/GroupNav-Infrastructure-Plan.md) states the core principle:
  *Mobile/client team must never be blocked waiting on backend data/compute layers.*
- `AuthStack` (User Pool, Identity Pool, Location Map) unblocks Flutter mobile developers immediately so they can build user authentication, map rendering, and rider flows while compute/database layers are being constructed.

### 2.3 Strict Avoidance of Temporary Workarounds
- Rather than bypassing the `cdk init` directory check with hacky file deletions or running a single-file script, we maintained all existing engineering documentation, initialized via standard CDK mechanisms, and recorded the issue formally.
